# 冀青赋能第一阶段：数据化与成长闭环设计

## 目标

将当前依赖前端静态数据和本地缓存的微信小程序 MVP，升级为可运营、可追踪的 Django 业务底座；为第二阶段青年成长发展 AI Agent 提供可信的资源和成长行为数据。

## 范围

本阶段仅实现业务数据化和成长闭环，不接入大模型、向量检索、RAG 或多 Agent。现有小程序页面和导航保持可用，并逐步改为调用后端 API。

## 架构

微信小程序通过 HTTPS API 访问 Django 服务。Django 保留已有用户注册、Token 鉴权与 YouthProfile 模型，并新增资源目录、用户动作和审核模型。开发环境使用 SQLite；模型与查询保持 Django ORM 兼容，以便部署时迁移到 PostgreSQL。第二阶段 Agent 服务通过受控 API 读取已发布资源、用户画像和成长事件。

## 数据模型

### 资源目录

- Policy：标题、地区、分类、适用人群、支持内容、条件、材料、流程、办理地点、电话、来源、发布日期、有效期、发布状态。
- Opportunity：标题、类型、单位、地区、待遇、学历/专业要求、截止日期、标签、详情、发布状态。
- Course：标题、分类、适用人群、时长、讲师、目标、材料、证书标记、发布状态。
- Activity：标题、时间、地点、主办方、适用人群、容量、议程、标签、发布状态。
- Mentor：姓名、角色、擅长领域、可预约时间、发布状态。

### 用户动作与成长记录

- Enrollment：用户、资源类型（机会或活动）、资源 ID、创建时间；同一用户对同一资源只能有一条记录。
- CourseProgress：用户、课程、完成状态、完成时间；同一用户对同一课程只能有一条记录。
- MentorConsultation：用户、导师、预约时间、问题、状态、创建时间。
- Favorite：用户、资源类型、资源 ID、创建时间；同一用户对同一资源只能收藏一次。
- GrowthEvent：用户、事件类型、资源类型、资源 ID、事件时间、附加数据，用于记录查看、报名、完成和咨询等行为。
- ReviewItem：资源类型、资源 ID、提交人、审核状态、审核意见、审核人、审核时间。

## API 与业务规则

- 资源 API 提供已发布、在有效期内的列表和详情；管理 API 提供创建、编辑、提交审核、审核通过/驳回和发布操作。
- 已登录用户可报名、收藏、完成课程、提交导师咨询；未登录请求返回 401。
- 服务端阻止重复报名、重复收藏和重复课程进度。
- 用户动作成功后写入对应业务记录和 GrowthEvent。
- 首页推荐按用户地区、发展意向、标签与资源标签进行确定性排序，返回政策、机会、课程和活动各一条；未完善画像时按发布时间和状态返回兜底资源。

## 前端迁移

- 保留现有页面信息架构。
- 将 policies、opportunities、courses、activities、mentors 从 utils/data.js 的展示依赖迁移至 API 获取。
- 详情页中的查看、报名和完成操作调用后端并刷新本地展示。
- “我的报名”“我的课程”“我的岗位申请”“我的导师咨询”展示真实用户记录。
- 管理后台使用真实审核接口；第一版仅依赖管理员身份，不建设多角色运营工作流。

## 错误处理与安全

- 后端验证请求体、必填字段和资源存在性；非法输入返回 400，未找到资源返回 404，未登录返回 401，重复动作返回 409。
- 生产部署前将 DEBUG 设为 False，使用环境变量配置 SECRET_KEY、数据库和 ALLOWED_HOSTS。
- 仅已发布资源可在普通用户端展示；政策和机会同时受有效期或截止日期约束。

## 测试与验收

- Django 自动化测试覆盖：模型约束、Token 鉴权、资源发布过滤、重复报名、课程完成、收藏、咨询与首页推荐规则。
- 每项新行为先写失败测试，再实施最小代码使测试通过。
- 第一阶段验收路径：完善画像 → 获取个性化资源 → 报名活动/岗位 → 完成课程 → 在“我的”查看真实记录 → 管理端审核资源。

## 非目标

- 本阶段不实现 AI 对话、职业规划生成、政策 RAG、向量数据库或鸿蒙端迁移。
- 不迁移现有静态演示数据的全部内容；先以种子数据或管理端录入支撑演示。
