# 冀青智引鸿蒙应用可真实使用精简版设计说明

> 版本：1.0  
> 日期：2026-07-24  
> 状态：功能范围已由项目负责人逐项确认，等待书面审阅  
> 项目：冀青智引——青年成长发展 AI Agent

## 1. 项目目标

开发一款面向河北县域发展意愿青年的鸿蒙手机应用。应用帮助用户建立青年画像、获得成长计划、查询政策与资源、采取成长行动并持续记录成长过程。

第一版定位为“可真实使用的精简版”，不是只供比赛展示的静态原型，也不在第一版追求完整商业产品的全部功能。

产品的一句话定位：

> 河北县域青年的个人成长服务中心，帮助用户了解自己、制定计划、找到政策与资源，并持续完成成长行动。

## 2. 与现有系统的关系

采用“鸿蒙成长中心＋现有后台”的方式：

- 鸿蒙应用负责页面、用户操作、本地缓存、本地通知和桌面成长卡片。
- 现有 Django 后台负责账号、青年画像、计划、政策、资源、报名、申请、收藏和成长记录。
- 小艺后续作为自然语言对话入口接入，但不阻塞鸿蒙第一版开发。
- 微信小程序继续保留，不作为鸿蒙应用开发的前置条件。

鸿蒙应用不得包含 `JIQING_AGENT_SERVICE_KEY`。该密钥只供后台与未来小艺平台之间使用。鸿蒙应用使用当前登录用户自己的登录凭证访问用户接口。

## 3. 已确认的产品决策

- 使用真实注册和登录。
- 第一版采用用户名与密码，不接短信验证码。
- 预留以后接入华为账号的扩展位置，但第一版不实现。
- 底部使用5个栏目：首页、规划、资源、助手、我的。
- 智能助手采用“功能按钮＋结果卡片”，第一版不做自由聊天。
- 资源行动包含收藏、岗位申请、活动报名、课程完成和导师咨询。
- 第一版只做中文。
- 第一版只支持鸿蒙手机竖屏。
- 加入本地通知提醒。
- 加入桌面成长卡片。
- 正常读取真实在线数据；断网时可查看最近一次成功加载的内容。
- 断网时不允许假装完成报名、申请或修改数据。
- 视觉采用温暖青年成长风。

## 4. 目标用户

主要用户为：

- 河北县域在校大学生；
- 应届或毕业不久的青年；
- 有返乡、县域就业、基层实践或创业意愿的青年；
- 需要职业方向、技能提升、政策和实践资源支持的青年。

第一版不按性别、年龄或其他敏感特征决定用户是否能获得服务。

## 5. 核心使用流程

### 5.1 新用户

注册账号  
→ 登录  
→ 完成分步骤青年画像问卷  
→ 查看画像总结  
→ 进入成长首页  
→ 获得第一份今日建议  
→ 生成成长规划  
→ 查看和使用推荐资源

### 5.2 日常使用

登录  
→ 查看今日任务  
→ 完成成长计划中的任务  
→ 查询政策或资源  
→ 收藏、报名、申请、学习或咨询  
→ 在成长档案中查看记录  
→ 根据新进展获得下一步建议

### 5.3 成长闭环

画像  
→ 规划  
→ 政策与资源  
→ 成长行动  
→ 行动记录  
→ 进度更新  
→ 新的今日建议

## 6. 信息架构

底部固定5个主栏目。

### 6.1 首页

首页负责回答：“我今天最应该做什么？”

内容顺序：

1. 用户问候和当前发展目标。
2. 今日最重要任务。
3. 当前成长计划进度。
4. 智能建议及建议理由。
5. 一项政策、一项岗位、一门课程和一个活动的重点推荐。
6. 临近截止的岗位、活动和计划任务。

首页避免展示过多列表。全部资源进入“资源”栏目。

### 6.2 规划

展示三个阶段：

- 7天计划；
- 1个月计划；
- 3个月计划。

每项任务展示：

- 任务名称；
- 推荐原因；
- 建议完成日期；
- 当前状态；
- 关联政策、岗位、课程或活动；
- “去完成”或“标记完成”操作。

完成任务后：

- 更新任务状态；
- 更新计划进度；
- 写入成长档案；
- 重新计算今日建议；
- 更新通知与桌面卡片。

“重新生成计划”必须先说明旧计划的处理方式，并要求用户确认。

### 6.3 资源

资源分为5类：

1. 政策；
2. 岗位；
3. 课程；
4. 活动；
5. 导师。

提供：

- 关键词搜索；
- 地区筛选；
- 资源类别筛选；
- 发展方向筛选；
- “只看适合我的”；
- “即将截止”。

每张推荐卡片展示：

- 名称；
- 类型；
- 地区；
- 截止时间；
- 推荐理由；
- 用户是否已经收藏、报名、申请或完成。

#### 政策详情

- 政策支持内容；
- 用户可能适用的原因；
- 仍需确认的条件；
- 申请材料；
- 办理流程；
- 发布单位；
- 有效时间；
- 官方来源。

#### 岗位详情

- 单位、地区、岗位类型；
- 工作内容；
- 学历和专业要求；
- 待遇或补贴；
- 截止时间；
- 推荐理由；
- 收藏和申请。

#### 课程详情

- 课程目标；
- 适合人群；
- 课程时长；
- 主要内容；
- 讲师或来源；
- 收藏、开始学习和标记完成。

第一版不建设完整视频播放器。

#### 活动详情

- 时间、地点、主办方；
- 活动介绍和流程；
- 适合人群；
- 名额和报名截止时间；
- 收藏和报名。

#### 导师详情

- 导师介绍；
- 擅长领域；
- 可咨询方向；
- 可预约时间；
- 提交咨询。

### 6.4 助手

第一版不做自由聊天，提供5个功能入口：

1. 分析我的画像；
2. 生成成长计划；
3. 查询适合我的政策；
4. 推荐成长资源；
5. 给我今日建议。

结果使用结构化卡片，不展示难以阅读的超长文字。结果卡片支持进入下一步：

- 查看详情；
- 加入计划；
- 收藏；
- 去报名或申请。

页面可以说明：

> 更多自然对话能力将通过小艺协同提供。

第一版不能把未完成的自由聊天伪装成可用功能。

### 6.5 我的

包含：

- 头像、昵称和当前发展目标；
- 画像完整度；
- 成长进度或成长积分；
- 我的画像；
- 我的收藏；
- 岗位申请记录；
- 活动报名记录；
- 已完成课程；
- 导师咨询记录；
- 成长档案；
- 通知设置；
- 隐私与账号设置；
- 退出登录。

## 7. 首次画像问卷

采用分步骤填写，不使用单个超长表单。

收集：

- 所在地区；
- 当前学历；
- 所学专业；
- 当前状态：在校、待业、就业、创业等；
- 发展方向：就业、创业、升学、技能提升等；
- 兴趣领域；
- 已具备能力；
- 当前最需要解决的问题；
- 期望获得的支持。

不强制收集：

- 身份证号；
- 精确住址；
- 与推荐无关的敏感信息。

用户修改发展目标时提示：

> 修改后可能影响成长计划和资源推荐，是否继续？

确认修改后，再询问是否重新生成计划。

## 8. 成长行动

第一版包含：

- 收藏政策和资源；
- 申请岗位；
- 报名活动；
- 完成课程；
- 提交导师咨询；
- 完成计划任务。

重要写操作使用确认流程：

1. 展示即将执行的内容；
2. 用户明确确认；
3. 向后台发送请求；
4. 返回真实成功或失败；
5. 成功后写入成长档案。

不得因为界面点击而先显示成功，再异步尝试真实报名。

## 9. 成长档案

以时间顺序记录：

- 完善或修改画像；
- 创建或重新生成计划；
- 完成计划任务；
- 收藏资源；
- 申请岗位；
- 报名活动；
- 完成课程；
- 提交导师咨询。

支持按记录类型筛选。第一版不开发复杂数据报表。

## 10. 鸿蒙端特色

### 10.1 本地通知

提醒：

- 今日成长任务；
- 活动即将开始；
- 岗位即将截止；
- 课程任务待完成；
- 阶段计划需要复盘。

用户可分别开启或关闭。避免在较晚时间主动提醒。

点击通知进入对应任务、岗位或活动页面。

### 10.2 桌面成长卡片

显示：

- 今日首要任务；
- 当前计划进度；
- 最近截止事项；
- 打开应用入口。

不显示：

- 详细个人画像；
- 导师咨询内容；
- 岗位申请结果；
- 账号和隐私信息。

用户退出登录后，卡片恢复为登录提示。

具体使用的鸿蒙API、SDK版本和能力名称，开发前必须以当时的HarmonyOS官方文档和比赛最新能力清单为准。

## 11. 离线与缓存

联网时从真实后台读取数据，并保存最近一次成功结果。

断网时允许查看：

- 最近一次画像；
- 当前计划；
- 最近推荐资源；
- 成长档案摘要。

断网时禁止：

- 注册和登录；
- 修改画像；
- 重新生成计划；
- 报名活动；
- 申请岗位；
- 完成课程；
- 提交导师咨询。

页面显示“当前离线，联网后可操作”，并提供重试按钮。

缓存必须按用户隔离。退出登录时清理当前用户的私人缓存。

## 13. 视觉规范

风格：温暖青年成长风。

- 主色：青绿色或蓝绿色；
- 背景：米白或浅灰白；
- 强调色：少量暖橙色；
- AI模块：轻微蓝绿渐变；
- 卡片：圆角、清晰留白；
- 图标：简洁线性图标；
- 动画：只用于页面反馈和进度变化。

避免：

- 大面积黑色背景；
- 过多霓虹和发光效果；
- 信息过密的政务页面；
- 为展示技术而添加的无意义动画。

## 14. 程序模块边界

鸿蒙项目建议拆分为：

1. 页面与可复用组件；
2. 统一路由；
3. 网络请求和API数据转换；
4. 登录状态管理；
5. 业务状态管理；
6. 按用户隔离的本地缓存；
7. 通知调度；
8. 桌面卡片数据；
9. 环境配置；
10. 开发样例数据。

后台地址只能在一个环境配置位置维护，不得散落在页面文件中。

页面不得直接依赖后台原始字段。网络层负责将后台返回转换成鸿蒙应用内部统一的数据结构，便于后台调整和测试。

## 15. 开发样例模式

为了让鸿蒙开发不被临时后台和小艺进度阻塞，可以提供不含隐私的本地样例数据。

- 样例模式只用于开发与页面预览；
- 正式构建必须连接真实后台；
- 样例模式下的报名、申请等操作必须标注为开发预览；
- 不得在比赛中把样例操作描述为真实后台成功；
- 样例数据结构必须和正式网络层输出一致。

当前后台身份和小艺绑定结构存在继续调整的可能。鸿蒙开发者应先通过独立API适配层接入，等后台接口冻结后再切换真实实现，不要让页面直接绑定临时字段。

## 16. 安全与隐私

- 仅使用HTTPS连接后台；
- 密码不以明文保存；
- 登录凭证使用鸿蒙系统安全存储能力；
- 不把后台服务密钥写入应用；
- 用户只能访问自己的画像和记录；
- 退出登录后清理私人缓存；
- 桌面卡片和通知不展示敏感详情；
- 写操作必须使用真实后台结果；
- 重复报名和重复申请由后台最终判断；
- 不向用户展示程序堆栈和内部错误信息。

## 17. 错误提示

采用用户可以理解的语言：

- “网络连接失败，请检查网络后重试。”
- “登录信息已过期，请重新登录。”
- “这个活动已经报名，不需要重复操作。”
- “该岗位已经截止，暂时无法申请。”
- “暂时没有找到符合条件的政策，可以调整地区或关键词。”
- “当前处于离线状态，联网后才能完成此操作。”

保留内部错误记录，但不直接显示技术错误码。

## 18. 验收流程

第一版必须走通：

1. 新用户注册并登录；
2. 完成画像问卷；
3. 查看画像总结；
4. 首页出现建议；
5. 生成7天、1个月、3个月计划；
6. 完成一项任务；
7. 查看政策、岗位、课程、活动和导师；
8. 收藏一项资源；
9. 申请一个岗位；
10. 报名一个活动；
11. 完成一门课程；
12. 提交一次导师咨询；
13. 在成长档案中看到记录；
14. 收到本地提醒；
15. 桌面卡片显示今日任务；
16. 断网后可以查看最近数据；
17. 断网时不能执行写操作；
18. 退出登录后不能查看私人缓存。

## 19. 测试要求

至少覆盖：

- 页面和底部导航；
- 注册、登录和登录失效；
- 首次画像流程；
- 计划生成、显示和任务完成；
- 五类资源列表与详情；
- 收藏、申请、报名、课程完成和咨询；
- 重复操作和资源截止；
- 智能助手五个入口；
- 按用户隔离的缓存；
- 离线只读；
- 退出登录清理；
- 通知开关和跳转；
- 桌面卡片更新；
- 常见鸿蒙手机屏幕尺寸；
- 真实后台接口联调。

## 20. 第一版明确不做

- 自由聊天；
- 社区、好友和动态；
- 支付；
- 直播；
- 完整视频课程播放器；
- 管理员后台；
- 全应用中英文切换；
- 手机以外设备适配；
- 复杂成长图表；
- 服务器消息推送；
- 短信验证码登录；
- 华为账号登录；
- 与当前核心成长闭环无关的鸿蒙能力。

## 21. 交付物

鸿蒙开发者最终应提供：

- 完整DevEco Studio工程；
- 可编译源码；
- 安装包或比赛要求的运行产物；
- 环境和后台地址配置说明；
- 页面和功能清单；
- 本地样例数据说明；
- 自动化测试；
- 模拟器和真机测试记录；
- 桌面卡片和通知配置说明；
- 已知问题列表；
- 1至3分钟核心流程录屏素材；
- README启动说明。

## 22. 完成标准

只有同时满足以下条件，才可称为“鸿蒙可真实使用精简版完成”：

- 核心验收流程全部通过；
- 使用真实账号和真实后台数据；
- 断网状态符合只读规则；
- 密钥和用户数据没有泄露；
