# 冀青智引小艺 Agent MVP 设计

## 目标

基于小艺开放平台与现有 Django 数据服务，构建面向河北县域青年的成长发展 Agent。MVP 完成“了解青年—形成画像—制定路径—解释政策—匹配资源—执行行动—记录成长”的可演示闭环。

## 赛题适配

作品响应 Agent 创新方向的三项核心要求：

- 成长陪伴：持续维护用户画像、成长计划和完成记录。
- 主动服务：结合地区、目标、时间和历史行为生成当日建议与到期提醒。
- 自然交互：使用小艺 Agent 提供文本与语音入口，通过 Skills 调用后端工具。

小艺开放平台承担自然语言理解、对话和工具编排；Django 承担可信数据、权限、业务规则、可执行动作和审计。作品不依赖团队自购第三方模型 API。

## 核心用户旅程

1. 用户在现有小程序生成短时有效的一次性绑定码。
2. 用户在小艺 Agent 中输入绑定码，将小艺用户身份与现有青年档案绑定。
3. 画像 Skill 读取档案，并追问缺少的地区、学历、专业、发展目标和能力信息。
4. 职业规划 Skill 生成 7 天、1 个月和 3 个月三个阶段的成长计划。
5. 政策 Skill 检索已发布且未过期的政策，返回适用条件、材料、流程、来源和有效期。
6. 资源 Skill 匹配岗位、课程、活动和导师，并说明匹配依据。
7. 用户明确确认后，Agent 才执行报名、收藏或完成任务等写操作。
8. 行动结果写入成长记录，并影响下一轮推荐和主动建议。

## 系统架构

### 小艺 Agent

- 识别画像补全、职业规划、政策咨询、资源匹配和行动执行意图。
- 维护当前对话上下文，调用受控 Skills。
- 将结构化工具结果转为青年易理解的表达。
- 不自行生成不存在的政策、岗位、课程或报名结果。

### Django Agent API

- 验证小艺服务调用凭据和外部用户绑定关系。
- 校验 Skill 参数、用户权限和写操作确认标记。
- 查询画像、政策、资源和成长记录。
- 保存成长计划、对话摘要、工具调用和执行结果。
- 对政策、资源和用户数据执行发布状态、有效期和数据隔离规则。

### Skills

1. `profile_context`：读取画像、缺失字段和最近成长行为；允许用户确认后更新画像。
2. `career_plan`：基于画像与资源库生成或更新三阶段成长计划。
3. `policy_search`：按地区、目标和关键词检索政策，返回可引用的结构化依据。
4. `resource_match`：匹配岗位、课程、活动和导师，返回匹配分和匹配原因。
5. `growth_action`：在显式确认后执行报名、收藏或任务完成，并返回真实业务结果。
6. `daily_suggestion`：根据计划截止时间、未完成任务和新资源生成今日建议。

前四项对应项目的四个核心 Agent 能力；后两项负责把咨询结果转为行动和主动服务。

## 账号绑定与身份安全

- 小程序登录用户调用绑定码接口，获得一次性随机码。
- 绑定码默认 10 分钟失效，使用一次后立即失效。
- 小艺 Skill 以平台提供的外部用户标识和绑定码调用绑定接口。
- 成功后保存外部用户标识与 Django 用户的一对一绑定，不保存小程序密码或登录 Token。
- 未绑定用户只能获得通用说明，不能读取个人画像、成长记录或执行写操作。

## 数据模型

- `AgentBindingCode`：用户、码摘要、过期时间、使用时间。
- `AgentUserBinding`：外部平台、外部用户标识、Django 用户、绑定时间、启用状态。
- `AgentConversation`：用户、平台会话标识、摘要、最近交互时间。
- `AgentMessage`：会话、角色、内容摘要、创建时间；MVP 不保存不必要的敏感原文。
- `GrowthPlan`：用户、目标、起止日期、状态、生成依据。
- `GrowthTask`：计划、阶段、标题、行动类型、关联资源、截止时间、完成状态。
- `AgentToolLog`：用户、Skill 名称、参数摘要、结果状态、耗时和创建时间。
- `ProactiveSuggestion`：用户、建议类型、内容、触发依据、计划时间、查看/完成状态。

## 工具返回协议

所有 Skills 返回统一 JSON：

```json
{
  "ok": true,
  "message": "面向用户的简短结果",
  "data": {},
  "sources": [],
  "requiresConfirmation": false,
  "errorCode": null
}
```

政策来源包含标题、发布机构、来源字段、发布日期和有效期。写操作在首次调用时返回 `requiresConfirmation: true`；只有第二次调用携带有效确认标识时才执行。

## 政策检索与可信回答

MVP 使用结构化检索增强生成：Django 先按发布状态、有效期、地区、类别和关键词检索政策，再将有限的结构化结果交给小艺组织语言。第一版不引入向量数据库；当政策文档数量明显增加时再增加文档分块和向量检索。

Agent 必须区分“可能适用”和“确认符合”。政策回答固定包含适用理由、不确定条件、所需材料、下一步办理方式和来源。没有检索结果时明确说明暂未找到，不生成替代政策。

## 主动服务

`daily_suggestion` 根据以下信息生成建议：

- 画像中的发展目标和地区；
- 成长计划中临近截止或逾期任务；
- 用户最近报名、学习和收藏行为；
- 新发布且匹配的政策、岗位和活动。

MVP 先提供“今日建议”查询和小程序卡片；若小艺开放平台具备并授权主动触达能力，再将同一建议接口连接到平台触发机制，不在未验证平台能力前承诺系统级推送。

## 错误处理与隐私

- Skill 请求无效返回稳定错误码，不让 Agent 猜测失败原因。
- 后端不可用时，小艺说明服务暂不可用，不声称已报名或已保存。
- 政策、资源仅返回已审核发布且未过期的数据。
- 每次查询按绑定用户隔离，禁止通过参数指定其他用户 ID。
- 近 3000 份调研数据仅用于脱敏聚合洞察和规则校验，不直接进入模型上下文。
- 对话记录只保存完成服务所需的最小摘要，支持后台停用绑定和清理记录。

## 测试与验收

- 模型测试：绑定码唯一性、有效期、一次性使用、外部身份唯一绑定。
- 权限测试：未绑定拒绝、用户隔离、服务凭据校验、写操作确认。
- 工具测试：画像读取/更新、计划生成、政策时效过滤、资源匹配、报名与收藏。
- 可信性测试：政策结果必须带来源；无结果时不得返回伪造政策。
- 对话联调：在小艺开放平台验证首次绑定、画像追问、政策咨询、资源推荐、行动确认和成长记录更新。
- 演示验收：5 分钟内完成“绑定—画像—规划—政策—资源—报名—今日建议”的主链路。

## 非目标

- MVP 不训练自有大模型，不依赖第三方付费模型 API。
- MVP 不建设向量数据库和复杂多 Agent 自主协作。
- MVP 不允许 Agent 绕过用户确认执行报名、收藏或修改画像。
- HarmonyOS 原生应用迁移作为下一独立阶段，不与小艺 Agent MVP 同时展开。
