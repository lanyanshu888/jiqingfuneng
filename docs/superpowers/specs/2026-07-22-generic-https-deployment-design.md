# 冀青智引通用 HTTPS 部署设计

## 目标

为现有 Django Agent API 增加可移植的生产启动层，使同一份代码能够部署到支持 Docker 的云主机或容器平台，并通过公网 HTTPS 地址供小艺开放平台测试态调用。此次工作不创建云账号、不购买资源、不绑定单一厂商，也不改变画像、规划、政策、资源和行动等业务逻辑。

## 方案选择

采用通用 Docker 镜像运行 Django，使用 Gunicorn 提供生产 WSGI 服务，通过平台或反向代理终止 HTTPS。相比华为云专用脚本，该方案便于迁移；相比临时内网穿透，它更适合比赛现场的稳定演示。

SQLite 继续作为本地和单实例比赛演示数据库。数据库文件通过可配置的数据目录持久化；如果所选平台不提供持久磁盘，则只允许用于可重新初始化的测试环境。多实例和正式用户环境不在本次范围内，后续应迁移 PostgreSQL。

## 组件与边界

- `Dockerfile`：构建轻量 Python 镜像、安装依赖、以非 root 用户运行服务并声明健康检查。
- `docker-entrypoint.sh`：启动前执行数据库迁移，可按显式环境变量选择是否写入演示数据，最后启动 Gunicorn。
- Django 设置：允许通过环境变量配置监听域名、数据库文件位置、代理 HTTPS、安全 Cookie、Secret Key 和 Agent 服务密钥；生产模式缺少关键密钥时必须快速失败。
- `.dockerignore`：排除虚拟环境、IDE 文件、日志、本地数据库和缓存，避免把本地数据或密钥打进镜像。
- 部署说明：给出构建、运行、健康检查、首次演示数据初始化及小艺 `openapi.yaml` 地址替换步骤。

## 启动与数据流

1. 容器平台注入生产环境变量和持久化数据目录。
2. 入口脚本执行 `manage.py migrate --noinput`。
3. 仅当 `JIQING_SEED_DEMO=true` 时执行演示数据命令；演示密码必须由环境变量提供。
4. Gunicorn 监听平台传入的 `PORT`，请求经平台 HTTPS 代理转发到 Django。
5. 小艺插件调用 `/api/...`；Django 继续校验服务密钥、用户绑定令牌和动作确认签名。

## 安全设计

- 生产模式禁止继续使用开发默认 `SECRET_KEY`。
- Agent 服务密钥不写入镜像、仓库、OpenAPI 文件或用户可见提示词。
- 默认不自动写入演示账号；初始化必须显式开启，并要求提供非默认密码。
- 镜像不包含仓库中的 `db.sqlite3`、日志和 `.venv`。
- 容器使用非 root 用户；HTTPS 由可信容器平台或反向代理负责。
- `ALLOWED_HOSTS` 必须通过环境变量限定实际域名，不在生产环境使用通配符作为文档默认值。

## 错误处理

- 迁移失败、生产密钥缺失或演示初始化参数不完整时，容器直接退出并输出明确错误。
- 健康检查只验证 `/api/health/`，不读取个人数据，也不需要用户令牌。
- 数据目录不可写时启动失败，避免服务表面正常但数据无法持久化。
- 小艺平台联调失败时，先区分 DNS/HTTPS、健康检查、服务密钥、用户绑定和业务校验五类问题。

## 测试与验收

- 新增设置测试：生产模式缺少 Secret Key 时失败；自定义 SQLite 路径和代理安全设置生效。
- 新增入口脚本静态检查或可执行行为测试，验证默认不初始化演示数据。
- 构建 Docker 镜像并启动容器，确认迁移完成、以非 root 用户运行、`/api/health/` 返回 200。
- 运行现有 Django 全量测试和小程序 Node 测试，确保部署改动不影响 Agent 闭环。
- 最终把真实 HTTPS `/api` 地址写入 `xiaoyi-agent/openapi.yaml` 后，再进入小艺测试态执行现有联调用例。

## 不在本次范围

- 自动购买或创建云资源。
- 自动提交、审核或发布小艺 Agent。
- PostgreSQL、高可用、多实例和自动扩缩容。
- 域名备案、证书申请及正式用户数据迁移。
